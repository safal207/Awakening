# Пробуждение / Awakening — первый путь в C# и 3D

**Действительный репозиторий:** [safal207/Awakening](https://github.com/safal207/Awakening)  
**Движок:** собственный воксельный C#/.NET 8 с OpenGL 3.3. Это не Unity, не Godot и не браузерная игра.  
**Визуальное доказательство:** [реальный игровой PNG/WebP](https://safal207.github.io/test-it-python/ai-path/assets/awakening.webp) и [источники capture](https://github.com/safal207/test-it-python/blob/main/dist/ai-path/assets/sources.json).

## Что уже находится в коде

- Воксельный мир, блоки, чанки и генерация ландшафта.
- Механика разрушения/установки блоков, 3D-камера и направление света.
- Экспериментальный FreeCity-модуль с NPC и сохранениями.
- Функциональные тесты, runtime-профайлер и CI.

Этот список подтверждён кодом и README; он **не означает**, что каждая функция протестирована на всех GPU или что игра готова к продаже.

## Четыре практические задачи для начинающего

### 1. Запустить и измерить

- Установить .NET 8 и совместимый OpenGL 3.3 драйвер на Windows.
- `dotnet build`, затем `dotnet run`.
- Записать версию ОС/GPU, 30 секунд обычной игры, скриншот и FPS (если профайлер включён).
- Ничего не модифицировать до успешного первого запуска.

**Готовый артефакт:** `docs/evidence/<дата>/first-run.md` с условиями и результатом.

### 2. Управление и интеракции

- Пройти глазами `src/Input.cs`, `src/Camera.cs`, `src/Game.cs`.
- Зафиксировать таблицу клавиш: WASD, Space/Ctrl, Shift, LMB/RMB.
- В sandbox-ветке изменить один безопасный параметр UX (например, текст подсказки) и снять **до/после**.
- Не объявлять «новой механикой» один поменянный цвет.

**Готовый артефакт:** маленький Pull Request со скриншотом и ручной проверкой.

### 3. Почему нужны тесты

- Запустить `dotnet run -- --functional-test` и `dotnet run -- --self-test`.
- Разобрать `src/FreeCity/FunctionalTests.cs`: повторное открытие яйца не начисляет бонус ещё раз.
- Добавить один самостоятельный негативный тест к **существующему** API прогресса, не обходя защитные условия.
- Сохранить точную команду и вывод CI.

**Готовый артефакт:** тест и описание исправленной/не подтверждённой проблемы.

### 4. Мини-проект в портфолио

- Выбрать **один** ограниченный feature: новый вид блока, палитру, визуальный маркер или сценарий поведения NPC.
- Сначала записать критерии приёмки и план проверки.
- Сделать правку с наставником, прогнать тесты, отметить оставшиеся ограничения.
- Записать 20–40 секунд реального геймплея и оформить PR.

**Готовый артефакт:** ссылка на PR, видео, скриншот, краткий README и тестовый отчёт.

## Контроль качества перед демонстрацией

| Проверка | Что проверяем |
|---|---|
| Сборка | `dotnet build --configuration Release` без ошибок |
| Функциональные тесты | `--functional-test` возвращает 0 |
| Сохранения | `--self-test` возвращает 0 |
| Снимок | Реальный runtime с коммитом и исходной командой, не AI-генерация |
| UX | Навигация, взаимодействие с блоками, адекватный FPS в известном окружении |
| Представление | Ясно отделены собственные изменения от существующего движка |

**Условия участия:** этот маршрут для обучения, не приглашение на оплачиваемую разработку и не гарантия трудоустройства. Наличие доступа к исходникам не заменяет проверку лицензий сторонних материалов.
